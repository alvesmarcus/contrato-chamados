## Problema e domínio

A empresa tem dificuldade para controlar os pedidos de suporte porque as informações ficam espalhadas em planilhas e mensagens. O novo sistema pretende organizar os chamados em um só lugar, permitindo que os clientes acompanhem suas solicitações e que os atendentes controlem os atendimentos. A aplicação será destinada à gestão e ao acompanhamento de chamados de suporte técnico.


## Escopo e pessoas usuárias

### Escopo inicial

- Cadastro de chamados;
- Consulta de chamados;
- Atualização do status dos chamados;
- Encerramento de chamados.

### Pessoas usuárias

1. Cliente
   - Objetivo: Registrar e acompanhar um chamado.

2. Atendente
   - Objetivo: Consultar, atualizar e encerrar chamados.

### Evolução futura
- Inclusão de notificações para informar os clientes sobre alterações no status dos chamados.
    
##  Requisitos funcionais

- O sistema deve permitir que o cliente registre um chamado.
- O sistema deve permitir que o cliente consulte seus chamados.
- O sistema deve permitir que o atendente atualize o status de um chamado.
- O sistema deve permitir que o atendente encerre um chamado resolvido.

##  Recursos do sistema

### Chamado

Possíveis informações:
- identificador;
- título;
- descrição;
- prioridade;
- status;
- data de abertura.

### Cliente
Possíveis informações:
- identificador;
- nome,
- contato. 

### Atendente
Possíveis informações:
- identificador;
- nome,
- contato. 

##  Fluxo prioritário - Registrar chamado

1. O cliente acessa a tela de abertura de chamado.
2. O cliente informa o título, a descrição e a prioridade do chamado.
3. A interface web envia os dados preenchidos para a API.
4. A API recebe os dados e o back end valida as informações do chamado.
5. O back-end cria o chamado e armazena as informações no banco de dados.
6. A API retorna uma confirmação de que o chamado foi registrado.
7. A interface informa ao cliente que o chamado foi registrado com sucesso.



 

## Decisões e dúvidas

### Decisões

- Decidimos que a primeira versão terá cadastro, consulta, atualização de status e encerramento de chamados.
- Decidimos criar dois perfis de usuários: cliente e atendente.

### Dúvidas em aberto
- Ainda precisamos decidir como será feita a identificação do cliente para que le possa consultar seus próprios chamados.
